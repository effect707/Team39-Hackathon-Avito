# Статус MVP и оставшиеся работы

Документ фиксирует фактическое состояние `dev` после объединения PR #3 и PR #4. Он нужен для быстрой сдачи: сначала проверяется сквозной demo-path, затем конкурентные гарантии и только после этого публичный deploy.

## Что реализовано

- список, карточка и альтернативы товаров из PostgreSQL;
- demo-идентичность через `X-Demo-User-ID`;
- join, восстановление состояния, позиция и выход из очереди;
- назначение FIFO по минимальному `ticket_no` под блокировкой товара;
- персональное право с TTL, worker для expiry и передача освободившейся единицы;
- checkout guard и идемпотентный demo payment endpoint для `success`, `failure`, `timeout`;
- PostgreSQL `LISTEN/NOTIFY`, SSE reconnect и повторное чтение REST-state;
- backend Compose с PostgreSQL, migrator, worker и двумя API-репликами;
- React frontend с реальным API по умолчанию и отдельным явным mock-режимом.

## Критично до финальной сдачи

1. Добавить конкурентные PostgreSQL-тесты из Definition of Done: 100 join при 5 единицах, promotion номеров 6 и 7, два worker, checkout против expiry и конкурентный повтор payment callback.
2. Для публичного full-stack demo развернуть frontend отдельно и задать ему `VITE_API_URL`, либо добавить общий reverse proxy. Текущий production workflow автоматически разворачивает только backend.

## Подтверждённые проверки

- `make verify` проходит полностью: форматирование, lint, Go unit/race, 64 frontend-теста, миграции/seed/constraints на временном PostgreSQL 17, OpenAPI/Compose validation и production builds;
- `make smoke` собирает Compose, проверяет health/readiness обеих API-реплик и доступность `api-2` после остановки `api-1`;
- ручной demo-path через разные API-реплики подтверждён: `GRANTED → CHECKOUT_PENDING → FAILED`, освободившаяся единица передана следующему `WAITING` с большим `ticket_no`;
- расширенная конкурентная матрица должна фиксироваться отдельными PostgreSQL-тестами, чтобы результат был воспроизводим в CI.

## Не блокирует основной demo-path

- поиск в header не подключён к серверному endpoint;
- после открытия конкретного товара SSE-подписка восстанавливается через `GET /queue/me`, но нет отдельного API списка всех активных очередей пользователя;
- нет `tools/loadgen` для воспроизводимого нагрузочного сценария;
- доменные Prometheus-метрики из расширенного плана не реализованы;
- две API-реплики опубликованы разными портами, прозрачного балансировщика и failover одного URL нет;
- настоящая авторизация, платёжный провайдер, TLS, Redis, Kafka и AI-интеграции не входят в MVP.
