# Ленивaя загрузка только модальных окон

## Цель

Убрать ленивую загрузку страниц приложения. Оставить разделение кода только для содержимого модальных окон авторизации/регистрации и очереди. Код каждой модалки должен запрашиваться лишь тогда, когда она действительно нужна пользователю.

## Границы изменения

- `HomePage`, `ItemDetailsPage`, `OrderPage` и `NotFoundPage` подключаются статическими импортами.
- Маршруты больше не оборачиваются в общий `Suspense`.
- `AuthModal` загружается через `React.lazy` только на маршрутах `/sign-in` и `/sign-up`.
- `QueueModal` загружается через `React.lazy` только при наличии ожидающей заявки и необходимости отрисовать модальное окно.
- `QueueRealtime`, запросы состояния очереди, бизнес-логика и публичные маршруты не меняются.

## Архитектура

Файл маршрутизатора напрямую импортирует страницы и передаёт их в `createBrowserRouter`. Существующий модуль `lazyPages.tsx` удаляется.

Для авторизации layout определяет, соответствует ли текущий путь входу или регистрации. Только при таком пути он рендерит ленивый компонент авторизации внутри локального `Suspense`.

Страница товара сохраняет текущую проверку состояния `WAITING`, но компонент очереди импортируется лениво. Пока соответствующий чанк загружается, локальный `Suspense` показывает компактный индикатор. Другие части страницы продолжают работать и не блокируются.

## Поведение при ошибках и загрузке

Локальные fallback-компоненты не заменяют всю страницу. Они занимают только область модального сценария. Существующие ошибки авторизации, входа в очередь и выхода из неё продолжают обрабатываться текущими компонентами после их загрузки.

## Проверка

Автоматический тест фиксирует архитектурное правило:

- страницы не используют `React.lazy` или динамические импорты;
- динамические импорты присутствуют только для модалок авторизации и очереди;
- условный рендер не запускает загрузку модалки до возникновения условия открытия.

После реализации запускаются frontend-тесты, линтер, проверка форматирования и production build.

## Риски

Основной риск — начать загрузку `AuthModal` сразу при монтировании layout и тем самым формально сохранить отдельный чанк, но потерять загрузку по требованию. Это предотвращается условным рендером lazy-компонента только на маршрутах авторизации. Для очереди условием остаётся состояние `WAITING` и показ модального сценария.
